# Алиса + Gemini на своём сервере

Навык для Яндекс Алисы, который отвечает на вопросы с помощью нейросети Google Gemini. Работает на вашем собственном VPS, без Vercel и без открытия портов дома.

Говорите «Алиса, запусти навык …» и задавайте вопросы как обычно. Если подключить Serper, навык умеет искать свежие данные: погоду, курсы, новости.

Основан на шаблоне [alice-gemini-serper-template](https://github.com/ruslanpodzorovraw-collab/alice-gemini-serper-template). Что добавлено:

- две модели параллельно: основная отвечает лучше, запасная выручает, если основная не успела;
- защита от чужих запросов по `skill_id`;
- быстрый ответ на служебный `ping` от Яндекса, без расхода квоты;
- закрытие навыка на «спасибо», «пока», «всё»;
- запуск как обычный сервис на Linux (systemd).

## Что понадобится

| Что | Зачем | Цена |
|---|---|---|
| VPS с Ubuntu 22.04+ или Debian 12+ **за пределами России** | там работает навык. Gemini API недоступен с российских IP | от ~200 ₽/мес, хватит 1 ядра и 512 МБ RAM |
| Домен, направленный на IP сервера | Яндекс принимает только HTTPS с настоящим сертификатом | бесплатно: [DuckDNS](https://www.duckdns.org) |
| Аккаунт Google | ключ Gemini | бесплатно, с лимитами |
| Аккаунт Яндекса | создание навыка | бесплатно |
| Аккаунт [Serper](https://serper.dev) — необязательно | поиск в интернете | 2500 запросов бесплатно |

> **О приватности.** На бесплатном тарифе Google может использовать ваши запросы для улучшения своих моделей. Не спрашивайте навык о том, что не готовы показать Google.

## Шаг 1. Получите ключ Gemini

1. Откройте https://aistudio.google.com/app/apikey и войдите аккаунтом Google.
2. Нажмите **Create API key** и скопируйте ключ.

**Если появилось «The request is suspicious»** или ключ не создаётся, сделайте ключ в Google Cloud Console:

1. Откройте https://console.cloud.google.com/apis/library/generativelanguage.googleapis.com и нажмите **Enable**.
2. Перейдите в **APIs & Services → Credentials → Create credentials → API key**.
3. В **API restrictions** выберите **Gemini API**. Google предложит привязать ключ к сервисному аккаунту: создайте новый, роли не нужны.
4. В **Application restrictions** выберите **IP addresses** и укажите IP вашего VPS. Тогда украденный ключ не будет работать ни с какого другого адреса.

Ключ храните как пароль: никому не отправляйте и не публикуйте.

## Шаг 2. Установите навык на сервер

Подключитесь к серверу по SSH и выполните:

```bash
git clone https://github.com/kdx019-max/alice-gemini-vps.git
cd alice-gemini-vps
sudo sh deploy/install.sh
```

Скрипт поставит Node.js, скопирует навык в `/opt/alice` и запустит сервис `alice`. В конце должно появиться `active` и строка с `"ok":true`.

Теперь впишите ключ:

```bash
sudo nano /etc/alice/env
```

Вставьте ключ сразу после `GEMINI_API_KEY=`, без пробелов и кавычек. Сохраните: `Ctrl+O`, `Enter`, `Ctrl+X`. Перезапустите сервис:

```bash
sudo systemctl restart alice
```

## Шаг 3. Откройте навык в интернет по HTTPS

Навык слушает только `127.0.0.1:8090`. Наружу его выпускает веб-сервер, у которого есть HTTPS. Адрес будет с секретной частью, чтобы его нельзя было угадать.

Придумайте секрет:

```bash
openssl rand -hex 12
```

**Вариант А — на сервере ничего нет (проще всего).** Поставьте Caddy, он сам получит сертификат:

```bash
sudo apt install -y caddy
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile   # замените alice.example.com на свой домен, SECRET — на секрет
sudo systemctl reload caddy
```

**Вариант Б — на сервере уже есть nginx с HTTPS.** Вставьте содержимое `deploy/nginx-location.conf` в нужный блок `server { … }`, замените `SECRET` и выполните:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Проверьте с любого компьютера, подставив свой домен и секрет:

```bash
curl https://alice.example.com/alice-SECRET
```

Ответ должен содержать `"ok":true`. Это и есть ваш **Webhook URL**.

## Шаг 4. Создайте навык в Яндекс Диалогах

1. Откройте https://dialogs.yandex.ru/developer → **Создать навык Алисы**.
2. Заполните:
   - **Название навыка** — **минимум два слова**, например «Мой умник». Одно слово Яндекс не принимает. Запускать навык будете этим названием.
   - **Примеры запросов** → «Запусти навык» + ваше название.
   - **Описание** — пара предложений о навыке.
   - **Backend → Webhook URL** — адрес из шага 3.
   - **Хранилище** → включите «Использовать хранилище данных в навыке», чтобы навык помнил разговор.
   - **Тип доступа** → **Приватный**. Модерация не нужна, навык будет доступен только вам.
   - **Категория**, **Имя разработчика** — любые.
   - **Иконка** — обязательна. Подойдёт `deploy/icon.png` из этого репозитория.
3. Нажмите **Сохранить**.
4. Скопируйте `skill_id` — это часть адреса страницы навыка вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Впишите его на сервере в `/etc/alice/env` в строку `ALICE_SKILL_ID=` и выполните `sudo systemctl restart alice`.
5. Откройте вкладку **Тестирование** и задайте вопрос. Навык должен ответить.
6. Нажмите **Отправить на модерацию** → **Отправить**. Приватный навык проходит без проверки, публикация занимает несколько минут.

## Шаг 5. Пользуйтесь

- «Алиса, запусти навык мой умник» — дальше спрашивайте подряд, без «Алиса».
- «Алиса, спроси у навыка мой умник, почему небо голубое» — один вопрос сразу.
- «Спасибо», «пока», «всё» — навык попрощается и закроется. Или «Алиса, хватит».

Пока навык открыт, **все** фразы уходят в Gemini, даже «включи музыку». Закрывайте навык, когда закончили.

Навык работает на колонках и в приложениях, где выполнен вход в тот же аккаунт Яндекса. Чтобы дать доступ семье, откройте в Диалогах вкладку **Доступ**.

## Если что-то не работает

| Что видно | Что проверить |
|---|---|
| Алиса не находит навык | Навык опубликован? В Диалогах статус должен быть не «Черновик». Колонка в том же аккаунте Яндекса? Название произносится так же, как записано? |
| Кнопка «Отправить на модерацию» серая | Не сохранилась иконка: загрузите её ещё раз, нажмите «Сохранить» и обновите страницу. |
| «Сервер пока не настроен» | В `/etc/alice/env` пустой `GEMINI_API_KEY`, или сервис не перезапущен. |
| «Не удалось подключиться к Gemini» | Ключ неверный, или ограничение по IP не совпадает с IP сервера. |
| «Не успела подготовить ответ» | Модель отвечает слишком долго. Проверьте, что `GEMINI_THINKING_BUDGET=0` и указана запасная модель. |
| В тестере «ошибка вебхука» | Откройте Webhook URL в браузере: должен быть `"ok":true`. Если `403` — неверный `ALICE_SKILL_ID`. |

Логи сервиса:

```bash
sudo journalctl -u alice -n 50 --no-pager
```

Ключи в логи не пишутся, но перед тем как кому-то их показывать, всё равно просмотрите.

## Настройки

Все настройки лежат в `/etc/alice/env`, после изменений нужен `sudo systemctl restart alice`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `GEMINI_API_KEY` | — | ключ Gemini, обязателен |
| `SERPER_API_KEY` | пусто | ключ поиска Serper; без него навык не ищет в интернете |
| `GEMINI_MODEL` | `gemini-3.5-flash` | основная модель |
| `GEMINI_FALLBACK_MODEL` | `gemini-3.5-flash-lite` | запасная модель, пусто = не использовать |
| `GEMINI_THINKING_BUDGET` | `0` | «рассуждение» модели; больше 0 почти всегда не укладывается во время |
| `GEMINI_MAX_OUTPUT_TOKENS` | `400` | максимальная длина ответа |
| `ALICE_SKILL_ID` | пусто | если задан, запросы от других навыков отклоняются |

**Почему не самая умная модель.** Яндекс ждёт ответ навыка примерно 4,5 секунды. Модели с «рассуждением» думают дольше 10 секунд и не успевают. `gemini-3.5-flash` без рассуждения отвечает за 1–3 секунды, а запасная `flash-lite` — меньше чем за секунду. Обе модели запрашиваются одновременно, поэтому бесплатная квота расходуется вдвое быстрее.

## Обновление

```bash
cd alice-gemini-vps
git pull
sudo sh deploy/install.sh
```

Файл `/etc/alice/env` при обновлении не перезаписывается.

## Для разработчиков

```bash
npm test
```

Тесты не ходят в сеть и не требуют ключей.
